Supabase

An open-source backend built around PostgreSQL. It gives a web page sign-in, a database API, access rules and live updates without a server of your own. This site explains how those parts work, with a small example you can build in an hour.

Supabase in one minute

A web page on its own can show a form, but a shared app needs more: it has to know who the user is, store data outside one browser, decide who may read or change that data, and sometimes show changes made by someone else. Those jobs usually need a backend.

Supabase provides that backend as hosted services. At its centre is a full PostgreSQL database. Around it sit Auth for sign-in, a Data API that turns tables into HTTP endpoints, Realtime for live changes, plus Storage for files and Edge Functions for server-side code [1].

The important idea: access rules live inside the database as Row Level Security policies. The browser can talk to the database API directly because PostgreSQL checks every request [4].

Our example

A live task board. Users sign in, pick a shared project and add tasks. Each user can only see and create their own tasks, and a second open window updates without a refresh.

  • Auth: email and password sign-in
  • PostgreSQL: two related tables with constraints
  • Data API: reads and writes from the browser
  • RLS: per-user access, tested on purpose
  • Realtime: new tasks pushed over a WebSocket
